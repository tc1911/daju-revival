## 1. 启动与热更

`assets/main.js` 不是游戏入口，是热更引导：

```js
localStorage.getItem("HotUpdateSearchPaths")
```

存在则 `jsb.fileUtils.setSearchPaths(paths)`，之后引擎从
`writablePath/blackjack-remote-asset` 加载 `project.jsc`，APK 内 JS 被覆盖。

离线包必须在读取前清掉：

```js
localStorage.removeItem("HotUpdateSearchPaths");
jsb.fileUtils.removeDirectory(writablePath + "blackjack-remote-asset/");
jsb.fileUtils.removeDirectory(writablePath + "blackjack-remote-asset/_temp/");
```

确认日志（大小写与源码一致）：

```text
!!!!HotUpdate main.js no hotUpdateSearchPaths
```

如果 APK 改了但行为没变，先确认这行日志，不要继续改 JS。

## 2. 账号与持久化

### 2.1 原版持久化模型

客户端不是“本地存档”游戏，设置和剧情进度主要走服务器：

```text
LocalStorage.setXxx
  → Common.chatInfo().setChatInfo(key, value)   // 内存数组
  → UserDefault.setXxx(key, value)              // 默认 persistLocal=false
      → chatStorage.Instance.chatCaches          // 内存 Map

UserDefault.getXxx(key)
  → fromLocal=false
  → chatStorage.Instance.getChatStorage(key)

Common.SynchronizeStorage()
  → sendMessage("storageChat", { storeList: chatInfo.getChatList() })
  → 服务器保存 → chatInfo.resetChatList()

Launcher.getChatStorage()
  → sendMessage("getStoreDataV2")
  → for (key in data) UserDefault.setString(key, data[key])
  → setLastChatId(data.last_chat_record_id)
  → 恢复 last target / chapter → getSpecialStatus() → changeScene()
```

### 2.2 离线包为什么清零

本地 fake `getUser` 不执行 `doLogin / SnsProxy.login`，而 `Common.Token.uid`
只在登录响应里赋值。`SynchronizeStorage` 的守卫是：

```js
if (L.uid && "" != L.uid) { ... }
```

所以 `storageChat` 不发；假 `getStoreDataV2` 又只回 `last_chat_record_id: 0`，
启动恢复被跳过。结果：设置只写内存、进度 key 全丢、剧情从默认节点重来。

### 2.3 根修复

`UserDefault` 六处默认参数从 `false` 改为 `true`：

```text
setBool / getBool
setNumber / getNumber
setString / getString
```

对应原版 `UserDefault` 模块 49706-49796（六个方法在 49739-49773）。
改后所有 `LocalStorage` key 自动落 Android 本地存储。

配套：

- `AudioPlayer.init`（模块 8633-8816，init 8657）补读 `off_music`，
  否则关闭音效只改开关，重启不静音
- 假 `getUser` 的 `newUser` 按本地 `lastChatId` 判断，`maxChatId` 用本地章节值
- 不要再用 `daju_state.json` / `daju_chat_store.json` 快照双写；
  双写会和真正持久化互相覆盖

### 2.4 关键 key

| key | 用途 |

| `chapter_maxchatId` | 已解锁章节进度 |

### 2.5 电量

内部电量 `0–10000`，UI 显示 `electricity / 100 + "%"`。每句剧情调用
`UserInfo.addElectricity(-cost)`；它直接改 `_electricity`，不经过 `setElectricity`。
原版顶栏按 `powerRecover` 间隔回补电量（12s 折算 1 点），低电量时触发提示；
这个回补会制造低值事件。

离线无限电量的稳定修法是在 `addElectricity` 入口对 `e < 0` 直接 return，
不要用 `setInterval(lockPower, 1000)` 反复覆盖。

## 3. 聊天图片预览

### 3.1 资源事实

包内 `assets/res/raw-assets/` 全部 UUID 命名，没有 `chatImg_*.png` 文件名。
逻辑路径 `sprites/chatImg/chatImg_<id>` 对应：

```text
res/import/<sf uuid[0:2]>/<sf uuid>.json   // cc.SpriteFrame
res/raw-assets/<tex uuid[0:2]>/<tex uuid>.png
```

`settings.js` 中：

- 1365 条 raw asset 映射
- 242 个 `sprites/chatImg` SpriteFrame（240 个 `chatImg_<id>` + 2 个特殊）
- 同名 `.png` 是 Texture2D；本地缩略图常见 300×300、200×200、150×150、465×185

APK 内 **没有 `chatImg_big`**；远程大图只是高清版，CDN 已停，离线不要依赖。

本地 id 覆盖：剧情 593 条图片对话（167 个 content id）、相册 171 个 serverId、
朋友圈/活动/八卦引用，全部本地。只有 240 之外的 id 才会缺图。

### 3.2 ImageView 预制体

`prefabs/ui/ImageView` 里：

- `img` 挂在 1×1 的 `dot` 节点上
- 原 `show()` 用 `img.node.getContentSize()` 计算 540 宽，未加载时得到 1px
- `show()` 先执行 `this.img.node.scale = 0`；回调不来时图永远不可见，但全屏按钮还在

### 3.3 远程图回调为什么不来

原生图片下载在 `jsb-adapter/jsb-engine.js:1525`：

```js
function downloadImage(item, callback) {
    var img = new Image();
    img.src = item.url;
    img.onload = function (info) { callback(null, img); };
}
```

问题：

- 没有 `onerror`
- `onload` 在 `src` 之后才赋值
- `src` 失败只派发 `error` 事件，没人监听

于是 `cc.loader` 的 `Downloader.handle` 不回调：不 resize、不 failSafe、遮罩一直留着。
更严重的是 `Downloader._curConcurrent` 只在回调里递减；远程图每失败一次泄漏一个并发槽，
`DOWNLOAD_MAX_CONCURRENT=64`，耗尽后所有图片（包括本地）加载停摆。

**离线不要把远程 URL 交给 `cc.loader.load`。**

### 3.4 LoaderManager / cc.loader 语义

`LoaderManager.loadAsset(path, cb, type)`（模块 32787-33124，约 33009）：

```js
var o = cc.loader.getRes(e, n);
o ? t(o) : cc.loader.loadRes(e, n, function(n, o) {
    if (n) { cc.warn("loadAsset error", e); t(void 0); }
    else t(o);
});
```

- 回调只有一个参数 `asset | undefined`
- 可能同步（缓存命中），也可能异步
- 失败回调 `undefined`，不是抛异常

`cc.loader.loadRes` 的坑：

- 同一路径可能同时注册 Texture2D（`.png`）和 SpriteFrame
- 不传 type 时可能拿到 Texture2D
- 三参 `loadRes(path, cc.SpriteFrame, cb)` 在部分版本里 type 会落到 progress 槽
- 稳妥写法是 `loadRes(path, null, cb)` + 自己判断 asset 类型

类型判断：

```js
function toFrame(asset) {
    if (!asset) return null;
    if (asset.getRect && asset.getTexture) return asset;       // SpriteFrame
    if (asset.spriteFrame) return asset.spriteFrame;
    if (asset.width !== undefined && asset.height !== undefined) {
        return new cc.SpriteFrame(asset);                       // Texture2D
    }
    return null;
}
```

尺寸读取顺序：

1. `sf.getTexture().width/height`（最稳）
2. `sf.getOriginalSize()`（`_originalSize` 为 null 时会抛，必须 try/catch）
3. `sf.getRect()`
4. 不要用 `img.node.getContentSize()`（加载前是 1×1）

### 3.5 原版点击链路

`ChatItem.onClickImageContentAction`（模块 11102-11973，图片逻辑 11854-11914）：

```js
t = ".../chatImg_big/chatImg_" + this._data.content + ".png";
Common.showBigImage(t);
```

`Common.showBigImage`（模块 14646-16244，16014）：

```js
LoaderManager.loadAsset("prefabs/ui/ImageView", function(prefab) {
    var node = cc.instantiate2(prefab);
    scene.addChild(node, 1000, "ImageView");
    node.getComponent("ImageView").show(remoteUrl);
}, cc.Prefab);
```

`ImageView.show`（模块 31118-31229，31180）原版只 `cc.loader.load(url, cb)`，
不判断 err；失败时 `tex` undefined，仍可能设空 frame。

### 3.6 离线验收标准

- 优先解析包内 `chatImg_<id>` 的 SpriteFrame；成功才创建全屏预览
- 远程回调不来时 1.5 秒看门狗关闭，不留下遮罩 + 1px
- 失败只 toast，不创建遮罩；点空白/返回键可关闭
- 连续点击先销毁旧层，避免叠层
- 长按保存：离线包 toast「离线版本不支持保存原图」，不要把死 URL 交给原生下载

### 3.7 踩过的坑

1. 用 `r.default.LoaderManager`：ImageView 模块里 `r=Common`，Common 没有 LoaderManager，
   点击即抛 `TypeError: Cannot read property 'loadAsset' of undefined`
2. 只改 `ImageView.show`，远程回调根本不来 → failSafe 永远不执行
3. 把 Texture2D 当 SpriteFrame 赋给 sprite → `textureLoaded is not a function`
4. 用 `getOriginalSize()` 不 try/catch → `cc.size(null)` 抛错
5. 没看门狗 → 遮罩 + 1px 一直留着，表现为卡死
6. `window.__dajuChatImageFrame` 有跨调用脏值风险；必须用完即清或校验 frame 名称

## 4. 构建链事实

`tools/pipeline.toml` 描述整条构建链，`tools/build.py` 只按表执行。
`profile` stage 只读 `work/tmp/project.shop.js`，`profile-native` 只读 `profile.apk`；
两者默认都不会自动重跑更上游。当前主链：

```text
nopay（merge + offline + local + monetization + album）
  → back → daily → shop → profile → profile-native
```

`project.final.js` 只由 `profile` stage 生成；`project.back.js` / `project.daily.js` /
`project.shop.js` 会被下游复用，改对应 patch 必须重跑对应 stage。
